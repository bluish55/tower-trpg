# AI-TRPG 스토리 협업 가이드

이 문서는 스토리 담당자가 게임에 콘텐츠를 추가할 때 참고하는 가이드입니다.

---

## 개요

이 게임은 AI(Claude)가 GM 역할을 하고, 플레이어가 선택지를 고르는 구조입니다.
스토리 담당자가 쓴 텍스트는 **GM에게 전달되는 프롬프트**가 되고, GM은 그걸 바탕으로 서술과 선택지를 생성합니다.

**중요:** 직접 대사나 서술을 쓰는 게 아니라, GM이 따라야 할 **지침과 설정**을 씁니다.

---

## 파일 구조

```
data/pages/
  persistent/     ← 항상 GM에게 전달 (세계관, 규칙 등 잘 안 바뀌는 것)
  floors/         ← 해당 층에 있을 때만 전달
    floor-1.md
    floor-2.md
    ...
  npcs/           ← 해당 NPC가 파티에 합류했을 때만 전달
    garret.md
    lira.md
    pio.md
    ...
```

> 이 md 파일들은 GM이 읽는 **지침**이다. 방·적·수치 같은 실제 게임 데이터는 `data/game-data.json` (아래 5번).

**새 콘텐츠 추가 위치:**
- 새 층/방 → `floors/floor-N.md` 수정
- 새 NPC → `npcs/이름.md` 신규 작성

## 1. 층/방 파일 (floors/floor-N.md)

### 파일 상단 (frontmatter)

```yaml
---
load: fetch
condition: floor:1
label: Floor 1
---
```

`condition: floor:1` — 플레이어가 1층에 있을 때만 GM에게 전달됩니다.

### 전체 구조

```xml
<floor id="1" name="성문">

  <mood>
    이 층 전체의 분위기. 빛, 냄새, 소리, 온도. 어린 시절 읽던 책의 어떤 장면인지.
    진우가 이걸 알아보는 방식 (익숙함 + 뭔가 잘못된 느낌).
  </mood>

  <rooms>
    <room id="1A" name="성문 앞 계단">
      공간 묘사. 지금 어떤 상황인지. 누가 있는지. 무슨 일이 벌어지고 있는지.
      Exit: 1B (안뜰)
    </room>

    <room id="1B" name="안뜰">
      ...
      Exits: 1A, up to Floor 2 (2A)
    </room>
  </rooms>

  <enemy id="armor" name="리빙아머" tier="minion">
    외형. 이 적이 이상한 이유.
    공격 패턴 (예고 동작 → 실제 공격).
    맞았을 때 어떤 느낌인지.
  </enemy>

  <beats>
    - 이 층에서 반드시 일어나야 할 서사 포인트 목록
    - GM이 자연스럽게 유도해야 할 순간들
    - 플레이어가 놓치면 안 되는 정보
  </beats>

</floor>
```

### 방 ID 규칙

`층번호 + 알파벳` 순서로 붙입니다.

```
1A, 1B, 1C ...  (1층 방들)
2A, 2B, 2C ...  (2층 방들)
```

출구는 반드시 명시해야 합니다. `Exit: 1B` 또는 `Exits: 1A, 1B`

### 적 tier 종류

| tier | 설명 |
|------|------|
| `minion` | 잡졸. 여러 마리 등장 가능. |
| `elite` | 강한 적. 특수 패턴 있음. |
| `boss` | 층 보스. |

## 2. NPC 파일 (npcs/이름.md)

### 파일 상단 (frontmatter)

```yaml
---
load: fetch
condition: companion:garret
label: Garret
---
```

`condition: companion:garret` — 가렛이 파티에 합류한 시점부터 GM에게 전달됩니다.

### 전체 구조

```xml
<npc_sheet id="garret">

  <who>
    이 캐릭터가 존재하는 이유. 세계관 안에서의 역할.
    하은의 무의식 안에서 무엇을 상징하는지.
  </who>

  <body>
    외형. 습관적인 자세나 동작.
  </body>

  <speech>
    말투 특징 (경어/반말, 특이한 어미, 버릇).
    저강도 상황 대사 예시 2~3개.
    고강도(전투/위기) 대사 예시 2~3개.
    희귀한 솔직한 순간 대사 예시 1~2개.
  </speech>

  <behavior>
    스트레스 받을 때 반응.
    기본 행동 패턴.
    쉬고 있을 때 모습.
    버릇. 감정을 숨기는 방식.
  </behavior>

  <flaw>
    핵심 결함. 한 문장.
  </flaw>

  <wrongness>
    이 캐릭터가 오해하고 있는 것. 진실이 아닌 것을 진실로 믿는 것.
  </wrongness>

  <stakes>
    두려워하는 것 / 원하는 것.
  </stakes>

  <goal>
    실질적인 목표. 지금 당장 무엇을 하려는지.
  </goal>

  <toward_pc>
    진우를 처음 봤을 때 반응. 어떻게 행동하는지.
    알고 있는 것 / 모르는 것.
    GM lock: 절대 하면 안 되는 것 (GM에게 주는 제약).
    likes (+1) / dislikes (-1): 신뢰도 오르내리는 행동.
    신뢰도 단계별 변화 (0~3).
  </toward_pc>

  <ability>
    능력 이름 (층당 1회 사용).
    신뢰도 3일 때 강화 효과.
    어떻게 보이는지 (동작/장면 묘사).
  </ability>

  <cheat_sheet>
    한 문단 요약. GM이 빠르게 캐릭터를 떠올릴 수 있게.
    말투 / 외형 포인트 / 핵심 행동 / 핵심 오해 를 담을 것.
  </cheat_sheet>

</npc_sheet>
```

### 신뢰도 단계 (0~3)

신뢰도는 플레이어의 행동에 따라 코드가 자동으로 계산합니다.
각 단계에서 NPC가 어떻게 달라지는지를 `<toward_pc>` 안에 명시하면 됩니다.

---

## 3. 작성 언어

**영문으로 작성하는 것을 권장합니다.**
Claude가 영어 프롬프트를 더 정확하게 따르기 때문입니다.

한국어로 작성해도 괜찮지만, 대사 예시는 한국어로 써도 됩니다 (실제로 가렛/리라/피오 대사는 한국어로 작성되어 있습니다).

---

## 4. 대충 써도 됩니다

아래처럼 메모 형식으로 줘도 변환해드릴 수 있습니다.

**NPC 예시:**
```
새 NPC - 마을 대장장이 노인
말 없음, 망치질만 함
진우한테 칼 고쳐줌
본인이 만든 무기로 탑이 지어진 걸 알고 있음
신뢰도 높아지면 비밀 통로 알려줌
```

**방 예시:**
```
3층 C구역 - 무너진 도서관
책이 공중에 떠 있고 페이지가 계속 넘어감
책 속 글자가 진우 이름을 씀
출구: 3B, 4층
적 없음, 탐색 위주
```

이렇게 주시면 형식에 맞게 변환해서 파일에 적용합니다.

## 5. 현재 구현된 것들

### 숫자와 방 데이터는 md가 아니라 `data/game-data.json`에

방 목록·출구, 적의 HP·행동 주기·약점, 동료 합류 조건, 보상 카드, 하은의 쪽지 문구, 시험 제한 턴은
전부 `data/game-data.json`에 있고 코드가 판정에 쓴다. md 페이지에 적힌 숫자는 GM이 분위기를 맞추는 참고일 뿐이라,
**수치를 바꿀 때는 json을 고쳐야 실제 게임이 바뀐다.** (위 1번의 방·적 형식은 GM 지침을 쓰는 방법으로만 참고)

### 판정 태그

GM이 선택지 끝에 붙이면 코드가 판정한다. 판정은 `2d6 + 보정 vs 목표`.

| 태그 | 판정 | 설명 |
|------|------|------|
| `[공격]` | 있음 | 적 방어와 비교, 무기 피해 |
| `[회피]` `[방어]` | 있음 | 이번 턴 적 공격 대응 |
| `[살핌]` | 있음 | 약점·쪽지 발견 |
| `[숨기]` `[몸쓰기]` `[말]` | 있음 | 숨기, 오르기·달리기, 설득·도발 |
| `[사용: 능력]` | 자동 | 보상 능력 (동료 능력은 동료가 알아서 쓴다) |
| `[공격: 이름]` | 있음 | 동료와 협공 (판정 +2, 반격은 그 동료에게) |
| `[동료: 이름]` | 없음 | 쓰러진 동료를 일으켜 세운다 |
| `[떠남: 이름]` | 없음 | 동료를 버린다 (이번 다이브 약속 결말 잠김) |
| `[이동: 방ID]` | 교전 중이면 있음 | 방 이동. 교전 중이면 이탈 판정(회피), 실패하면 못 나간다 |
| `[선택]` | 없음 | 위험 없는 행동 |

결과는 대성공 / 성공 / 실패 / 대실패 4단계 (부분 성공 없음).

### 현재 구현된 층

1~5층 전부 (1층 성문, 2층 안개숲, 3층 가라앉은 도시, 4층 거울 회랑, 5층 빈 페이지).
결말 5종: 약속 / 강제 / 기사 / 혼자 / 머묾.
